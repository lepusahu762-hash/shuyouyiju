# 模板中心

进入 `/app/templates`，点击“添加模板”，填写名称、用途分类、项目目标，以及规则草稿或报告提纲（至少一项），保存到当前账户。内置模板可直接使用，也可“另存为我的模板”后修改。个人模板支持编辑，保存后版本递增。

点击“使用模板”，填写新项目名称并确认，后台创建独立项目并保存当时模板内容。进入资料页后，可以查看草稿和提纲，点击“完善并保存规则说明”将规则草稿带入现有文本编辑器，完善后再保存。之后仍须上传本次资料、指定规则资料、逐项关联真实来源并确认统计规则。

模板不是数据集、计算方案或核验结果，不扩大现有计算引擎的能力。套用不会复制上传文件、人工确认状态、计算结果、修订或导出。模板中的占位说明必须由用户按本次资料完善；保存文本不等于规则已确认，更不等于核验通过。修改原模板不会影响已经创建的项目。

## 实现

- `backend/app/templates.py`：当前账户模板列表、新增、带版本号编辑、使用模板创建项目、读取项目模板快照。
- `project_templates` 和 `project_template_snapshots` 是新增SQLite表，应用启动时自动创建；不改变或清空已有表。项目和快照在同一事务中保存。
- 服务端按账户校验读写权限；内置模板不可覆盖；编辑和套用检查版本；同一创建请求重试返回原项目，避免重复创建。
- 前端 `TemplatesPage.tsx`、`ProjectTemplatePanel.tsx`、`Templates.css`；调用真实API，失败时保留表单输入并显示错误。
- 尚无模板删除、团队共享、文件导入模板、已有项目覆盖套用或富文本报告生成，本轮未实现也未标为完成。

## 验证方式

后台：`python -m pytest tests/test_templates.py tests/test_accounts.py tests/test_rule_onboarding.py -q`（在backend目录，测试使用独立临时数据库）。

前端：构建、lint；`node scripts/test-templates.cjs`在本机真实服务上注册新合成账户，检查模板增改、保存、创建项目、草稿转规则文本、快照隔离、错误恢复和1440/390/320布局。需要已有Playwright和浏览器，可用 `PLAYWRIGHT_MODULE_PATH`、`BROWSER_EXECUTABLE` 指定路径；不会修改依赖锁或调用AI。验收截图及JSON默认保存到忽略目录 `artifacts/template-browser`，不保存密码和会话。
