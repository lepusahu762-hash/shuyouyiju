## 2. 产品定位与边界

一句话定位：把数据、图表和报告连接起来，让每条结论都有可核对的依据。

对外主文案：让报告中的每个结论，都有可核对的数据依据。
辅助文案：上传表格与报告，完成数据分析、结论核验、证据追溯和修改复核。

重点用户：
1. 撰写调查报告、课程报告的学生与教师。
2. 整理活动反馈、运营数据、阶段总结的组织与小团队。
3. 需要重复检查报表、统一统计口径的业务人员。

两条入口，共用同一项目与证据体系：
- 我有数据，想分析：导入资料 → 提问分析 → 将结果加入报告草稿 → 核验 → 修改交付。
- 我有报告，想核验：导入报告及依据 → 核验 → 补充分析或材料 → 修改复核 → 导出。

“核验”的含义是检查结论是否与提供的数据、范围和规则一致。它不自动证明原始数据真实，也不把相关关系升级为因果关系。

首版重点覆盖描述性统计与报告一致性：数量、总和、均值、比例、增减、分组比较、排名、图表数值与口径。显著性检验、预测、因果推断等没有对应工具与前提检查时，返回能力边界或证据不足。

## 6. 页面 3：登录与注册

默认方案：邮箱与密码登录；提供注册、密码显示开关、找回密码、必要的邮箱验证。使用成熟认证实现，具体依赖在编码时核实维护情况与官方文档。

布局：左侧简洁品牌说明与一张证据卡，右侧认证表单；手机只保留表单和简短品牌信息。

需要完成的状态：
- 登录、注册、验证邮件已发送、邮箱验证完成、找回密码、重置完成。
- 字段错误直接显示在对应输入框下，不用无意义的“系统异常”。
- 提交时防止重复点击；失败保留邮箱，密码按安全策略处理。
- 会话过期保留尚未保存的编辑草稿，重新登录后恢复。
- “返回体验示例”始终可用，避免用户卡在注册页。
- 已登录用户进入此页时返回工作空间或上一个合法目标。
- 密码恢复链接应有有效期并只能使用一次；不能只做发送成功的假提示。

部署前必须接通并验证邮件发送与恢复流程。若尚未具备邮件服务，暂时以明确的邀请测试模式提供评审账户与访客演示，不展示不可用的开放注册/找回入口。

隐私说明按实际数据处理实现填写。第三方登录、手机验证码作为后续扩展，不在首版并列多个无效按钮。

## 7. 页面 4：我的工作空间

登录后默认进入这里；也可设置“返回上次项目”。

### 排版

第一行：页面标题、搜索框、“新建项目”主按钮。  
第二行：当前需要处理的任务与快捷入口。  
主体：项目列表，默认表格，可切换卡片。  
底部或右侧：最近打开、收藏项目、使用帮助入口。

最多放 3 个有实际意义的统计：进行中的项目、待确认事项、已生成交付件。统计必须来自当前账户的真实数据；新账户为零。

### 项目列表字段与动作

字段：项目名称、类型、资料数、当前阶段、待确认数量、最近修改时间。
筛选：全部、进行中、待我确认、已完成、已归档。
排序：最近修改、创建时间、项目名称。
动作：继续、重命名、置顶、复制、归档、移入回收站。

“复制项目”默认复制输入和规则，另行说明是否复制报告草稿；不继承旧项目的“已经核验”状态。已有结果可以作为历史快照保留，但新副本需要重新确认。

### 新建项目弹窗

只问三件事：
1. 项目名称。
2. 目标：分析数据 / 核验已有报告。
3. 从空白创建 / 使用模板 / 使用示例。

创建后进入资料页，不强迫用户填写团队、行业、职业、预算等与当前任务无关的信息。

首次使用空状态：“先放进一份表格，我们帮你找到可以分析的问题。”配上传入口和体验示例。已有项目时不重复播放入门引导。

## 8. 页面 5：资料与口径

这是防止后续算错、用错数据的基础页面。

### 桌面布局

左侧约 24%：文件列表，分“数据表 / 报告 / 图表图片 / 定义资料”。  
中间约 50%：所选文件预览与字段映射。  
右侧约 26%：本项目统计规则、范围、异常提醒及确认操作。

### 文件范围

首版支持：
- CSV、XLSX：工作表选择、表头识别、字段类型和单位、数据预览。
- DOCX、粘贴文本：导入待核验报告，保留可定位的标题与段落。
- PNG、JPG：导入图表图片。
- TXT、DOCX、可提取文本的 PDF：导入指标定义、问卷说明、规则文档。
- 扫描 PDF、复杂合并单元格、宏文件、超大文件不默默承诺支持；能处理时说明能力，不能处理时给出转换办法。

文件初始限额建议：每个文件 20 MiB、单数据表 5 万行、项目 20 个文件。均作为待压测的配置值，不在实测前宣传为已实现性能。超限提示实际限制、当前大小及拆分建议。

### 关键功能

- 拖拽或按钮上传；展示每个文件的真实上传与解析状态。
- 预览行数、列名、工作表、编码和字段类型。
- 让用户将“满意度”“满意情况”等原字段映射到相应指标；AI 推荐映射需要显示依据和可修改入口。
- 发现缺失、重复、类型错误、日期格式不一；显示受影响行，不自动删除。
- 原始文件只读保留。任何清洗都形成处理版本并记录规则，允许撤回。
- 同名文件上传时选择“新增资料”或“替换成新版本”，保留旧版本关系。
- 设置统计期间、对象范围、过滤条件、单位、舍入方式和比较基准。
- 指标规则明确分子、分母、纳入/排除条件。规则缺失时不能自行认定唯一口径。
- 规则来源显示文件名、章节/条目、原文片段及版本。
- 多份定义冲突时列出冲突并请求选择；用户选择记录为本项目规则。
- 图片放大、旋转和识别结果对照。看不清的数字需人工确认。
- 未确认的字段、口径或图片数值可以阻止相关核验，其他独立部分可继续。
- 完成后主按钮按目标显示“开始分析”或“开始核验”。

## 9. 页面 6：数据分析

让“数据分析”成为平台真实能力，而不是只有核验。

### 布局

左侧：当前数据表、字段与筛选器。  
中间：分析结果区域，以结论、图表、数值表展示。  
右侧可折叠：当前结果的依据。  
提问框固定在分析区底部；提供与已有字段匹配的建议问题。

### 支持的具体操作

- 自然语言提问：“各学院满意率是多少？”“本月比上月增长多少？”。
- 自动建议适用的描述性分析，不凭空建议数据里不存在的维度。
- 显示拟使用的字段、范围和口径；含糊问题先给简短选择。
- 受控工具计算数量、去重数量、总和、均值、比例、增减、分组比较和排名。
- 生成柱状图、折线图、分组对比表等适当图形；没有时间字段时不硬生成趋势。
- 图表切换不会改变数据；筛选会产生新的结果版本。
- 点中图形可查看对应数据子集；显示单位、范围、样本量、来源和计算规则。
- 结论与数字共用计算结果对象，避免图表与解释各算一遍导致矛盾。
- 保存有依据的结果；可收藏、“加入报告草稿”、下载图表与数据。
- 继续追问“为什么 A 学院最低？”时区分数值比较与原因推断；没有原因资料时不能编故事。
- “加入报告”保留引用和结果标识，进入草稿后仍需要按最终报告上下文复核。

任一结果至少包含：问题、范围、数据版本、规则版本、计算方式、结果值、样本量、来源链接、生成时间与限制。

## 10. 页面 7：结论核验

这是作品最需要打磨的页面。

### 布局

顶部：项目名、当前范围、资料版本、真实任务状态、开始/取消/重新核验。  
内容区默认三栏：报告约 36%、核验事项约 26%、证据约 38%。允许调整宽度。  
辅助追问放在选中结论的证据区，不遮挡报告正文。

### 三栏内容

报告栏：标题层级、正文、可核验句子、颜色标记、段落定位。
事项栏：与数据一致、存在差异、证据不足、需要确认、待复核；支持类型筛选和下一条。
证据栏：结论解释、原始数据、计算过程、规则来源、图表对照，按当前问题展示适用页签。

点击事项时，报告句子和对应的数据行/列同步定位。表格中既能看计算使用的行，也能看到“为什么排除其他行”。虚拟滚动不能破坏原始行定位。

### 五个结论状态

| 状态 | 具体含义 | 用户下一步 |
| --- | --- | --- |
| 与数据一致 | 在当前资料、规则、范围下有依据支持 | 查看依据或继续 |
| 存在差异 | 给定口径下报告与计算/图表结果不一致 | 查看建议、修改或说明保留原因 |
| 证据不足 | 缺少判断所需资料 | 补资料或保留未解决标记 |
| 需要确认 | 字段、范围、定义、识别内容存在歧义 | 作出选择后继续 |
| 待复核 | 依赖的报告、数据、范围或规则已变更 | 重新计算并核验 |

颜色配合文字和图标。不要用含义不清的“可信度 87%”，不要把人工点了接受变成“已验证”。

### 核验类型

1. 数值：总数、均值、比例、增减、名次是否一致。
2. 统计口径：分母、样本纳入标准、去重、加权方式、有效回答口径。
3. 范围：时间区间、对象范围、分组、单位和比较基准。
4. 图表：标签、单位、图形对应数值与报告是否一致；识别含糊时要求确认。
5. 证据：报告结论是否超出数据支持范围；未有基期、未有实验条件时说明限制。
6. 内部一致性：同一指标在不同段落、表格、图片中的表述是否矛盾。

### AI 的实际工作方式

- 提取报告中的待核验陈述，将复合句拆为多个可检查项。
- 检索当前项目的指标定义和规则文档，定位相关条目。
- 形成限定范围的工具计划，调用查询与计算工具。
- 校验工具参数和输出结构；数值由计算工具产生。
- 将工具结果与报告、图表识别结果比较，输出状态、解释和引用。
- 遇到歧义暂停该项并请求确认；不强行凑出结果。
- 用户修改后重新核验，保留旧结果与新结果的关联。

这里采用一个受控的核验工作流即可，不以堆多个 Agent 数量作为技术目标。Function Calling 负责连接实际计算和检索功能；是否增加 MCP 取决于以后需要接入的数据源。

页面展示“已提取 6 条陈述”“正在检索统计说明”“3/6 条已完成”等真实工作事件。不得生成虚构的内部思考过程、假进度或工具调用记录。

## 11. 页面 8：修改与交付

### 排版

顶部：本次核验范围、版本、处理进度。  
中间：原稿与修订稿并排比较；窄屏切换或上下排列。  
右侧：每处修改的原因、依据与操作。  
底部：未解决事项、重新核验、导出按钮。

### 需要完成

- 每项建议可“接受修改 / 自己编辑 / 保留原文并说明原因”。
- 支持撤回单项修改，查看此次操作影响了哪些句子。
- 仅把通过自动复核的项目显示为一致；人工保留仍保留原有证据状态。
- 批量接受前先列出涉及的修改。口径或含义有歧义的项目不能批量越过确认。
- 修改报告会更新报告版本，并使受影响的核验结果待复核。
- 范围、数据或规则改变时提示需要重新核验，旧结果作为历史快照。
- 可导出含未解决事项的报告，但须在导出内容中显著标注，不能使用“全部通过”封面。
- 导出前预览题名、作者可选、日期、来源、未解决项和版式。

### 首版交付格式

| 格式 | 内容 | 验收要求 |
| --- | --- | --- |
| PDF 核验报告 | 结论概览、问题、证据、计算、规则、范围、限制 | 中文不乱码、图表清晰、分页完整 |
| DOCX 修订稿 | 修订后的报告正文与来源说明 | 生成可编辑的新文档；不承诺完全还原任意原稿复杂版式 |
| XLSX 问题清单 | 句子、问题类型、原值、计算值、状态、证据位置 | 单位与数字清楚，防止用户文本被误识别为可执行公式 |
| 图表图片 | 当前结果图、标题、单位和来源说明 | 下载与当前筛选、数据版本一致 |

每份交付件记录项目、报告版本、数据版本、规则版本、筛选范围、生成时间及未解决事项。后续数据变化不覆盖旧文件；旧导出页明确“历史版本”。

## 12. 页面 9：模板中心

“模板”包含规则和报告结构，不仅是换封面。

首版内置：调查反馈、活动总结、简单经营月报三类。
每个模板有：适用问题、所需字段、推荐统计口径、报告结构、示例和使用入口。

支持：
- 查看模板详情。
- 用模板新建项目。
- 复制模板后修改为个人版本。
- 收藏模板。
- 从已有项目提取已确认的规则，另存个人模板。

规则知识库在资料页承担真实检索；模板中心负责可复用的创建入口，两者不能仅仅用卡片外观冒充 RAG。

公开模板不得夹带用户私有资料。个人模板默认私有。模板市场、支付购买和公开投稿审核留到后续版本。

## 16. 视觉设计规范

方向：浅色、清楚、可靠，有数据工具的精确感和报告阅读的舒适感。

### 建议色彩与字体

- 页面底色：#F6F7F9；内容底色：#FFFFFF。
- 主文字：#172B2A；次文字：#596968。
- 主色：#126B62；浅主色背景：#E8F3EF。
- 分隔线：#DDE4E5。
- 差异：偏红；需确认：琥珀色；证据不足：中性蓝灰；一致：绿色；待复核：文字加时钟标识。实际文字/底色组合需测对比度。
- 中文优先使用系统可用字体，例如 PingFang SC、Microsoft YaHei；避免依赖不稳定的外部字体加载。
- 正文 15–16px；次要标记可 13–14px；关键标题 24–32px。数字采用等宽数字，表格数值右对齐。
- 间距主要采用 8px 的倍数；面板圆角 10–14px；阴影轻且少。

### 最值得精修的 6 个位置

1. 首页右侧的“报告—计算—依据”交互，让品牌价值能看见。
2. 核验工作台的联动高亮，文字、数据、规则同时准确定位。
3. 图表与表格的数值、单位、轴标签、图例排版。
4. 修订前后对照，差异标记清楚但不满屏红绿。
5. 导出的 PDF：封面、摘要、图表、证据引用、页眉页脚与分页。
6. 空状态、首次上传、任务进行中、错误恢复等细节。

### 布局与响应式

- 公共页面内容宽度约 1200–1280px；工作台利用可用屏幕宽度。
- 桌面侧栏约 220px，可收起为窄栏。
- 宽屏三栏；空间不足时隐藏固定证据栏，改为可打开的证据抽屉。
- 平板两栏或页签；手机将“报告 / 事项 / 证据”切换为三个页签，保留选中项。
- 表格在自己的区域横向滚动，不让整个网页出现横向滚动条。
- 手机能完成查看与基本核验；大表格编辑强调桌面体验。

### 动效与无障碍

- 普通过渡约 160–220ms；重点用于选择、展开和任务反馈。
- 不采用持续漂浮的大量装饰，不让滚动动效阻断阅读。
- 支持减少动画偏好、键盘导航、明确焦点样式、表单标签和可访问的弹窗。
- 颜色之外保留状态文字与图标；图表提供可阅读的数据表。
- 自动滚动只在用户主动定位时发生；流式解释不能持续抢走阅读位置。

## 17. 容易漏掉的交互和异常细节

| 情况 | 产品行为 |
| --- | --- |
| 文件尚未上传 | 解释需要哪类资料，提供示例入口 |
| 部分文件解析失败 | 保留已成功文件；指出失败文件与原因，单独重试 |
| CSV 编码、分隔符不对 | 展示预览与选择项，避免乱码直接进入计算 |
| 表头重复、工作表过多 | 提示选择或重命名映射，不静默覆盖 |
| 分母为零 | 显示无法计算及原因，不显示 Infinity 或 0% |
| 空值不等于零 | 区分处理，记录排除/填补策略 |
| 数据被筛成零条 | 说明当前筛选无数据，给清除筛选入口 |
| 并列名次 | 明确采用的排名规则，不生成唯一第一名 |
| 四舍五入差异 | 按确认的小数位判断；同时展示未舍入值与展示值 |
| 增长与百分点混淆 | 显示原值、现值和两种计算定义 |
| 图片数字看不清 | 定位图片区域，展示候选或人工录入入口 |
| 同一指标有多个定义 | 列出来源冲突，确认后记录规则版本 |
| AI 超时、限流或不可用 | 保留资料和已完成结果，可重试；不假装完成 |
| 任务只完成一部分 | 逐项显示状态，未完成项不能进入一致数量 |
| 用户离开工作页 | 后端任务继续或按明确策略取消；任务抽屉可找到 |
| 用户连续点开始 | 防重复创建同一任务，显示已运行任务 |
| 核验运行中修改资料 | 当前运行绑定旧快照，新资料提示待复核；不把旧结果覆盖新状态 |
| 更改范围 | 更新数量、标签、图表和依赖状态；提示报告中对象名称也要变 |
| 会话过期 | 重新认证后恢复任务上下文和未提交草稿 |
| 自动保存失败 | 明确“未保存”，提供重试；不能继续显示“已保存” |
| 两个标签页同时编辑 | 检测版本冲突，保留两份内容供选择 |
| 接受了 AI 修改 | 状态为待复核，完成复核后才显示核验结果 |
| 手动保留问题句 | 保留原因，不抹去差异状态 |
| 收藏来自旧版本 | 显示历史版本，支持重新运行 |
| 导出失败 | 保留配置与任务，允许重新生成，不重复污染记录 |
| 找不到项目/无权访问 | 给返回入口，不泄漏他人的项目名和内容 |
| 删除资料 | 列明相关依赖，确认后处理；引用失效状态明确 |
| 页面刷新/前进/后退 | 保留筛选与选中项，不能回到完全空白 |
| 网络断开 | 显示连接状态，保护草稿，不显示虚假成功 |
| 用户输入含 HTML/公式 | 文本安全渲染；导出时防公式注入 |
| 访客演示用量耗尽 | 显示真实提示，可查看标明时间的已保存示例；不伪造实时调用 |

## 18. 数据与工程约定

这一节供 Codex 实施使用，不在普通用户页面强制展示。

### 架构选择

沿用已创建的 React + TypeScript + Vite 前端，不重复创建另一套前端工程。
建议新增 Python 后端，统一负责解析、计算、AI 调用、任务、认证及导出。
数据库保存账户、项目、规则、结果、版本、操作记录；原文件单独存储。
开发期可采用轻量数据库，公网多用户部署采用适当的持久化数据库与文件存储；持久化必须经过重启验证。

模型接入沿用前期讨论的阿里云百炼方向，实际可用模型、图像能力、配额和费用在接入时核实。做统一模型适配层，不把具体模型名称写死在业务组件。缺少真实凭据时，可以继续前端和计算实现，但 AI 集成项应明确标为待接通。

### 主要对象

User、Project、Asset、AssetVersion、DatasetSchema、Rule、RuleVersion、ReportRevision、AnalysisResult、Claim、VerificationRun、Finding、Evidence、ReviewAction、ExportArtifact、Favorite、Template、TaskEvent。

每个私有对象关联 owner/project；后端校验权限。
所有核验运行绑定：
- 数据版本。
- 报告版本。
- 规则版本。
- 筛选范围及计算参数。
- 工具/算法版本。
- 模型配置及运行时间。

证据引用使用稳定的标识和位置：文件版本、工作表、源行标识/单元格、段落、条目或图片区域。前端排序与过滤不得改变原始来源标识。

### RAG 与工具

规则文档解析 → 按语义与结构切块 → 建立可检索索引 → 根据指标及问题检索 → 返回原文和位置 → 在生成结论时绑定引用。

检索范围限制在当前用户、当前项目或已授权模板。规则冲突和找不到依据必须有明确分支。不要让上传文件中的“忽略指令”等文字改变系统操作权限。

计算工具使用明确的参数结构与白名单操作。模型可以请求数量、分组、筛选和比例等计算；后端检查字段和范围。首版不执行模型任意生成的 Python、SQL 或系统命令。

工具输出结构化；先做数值与来源校验，再生成解释。RAG 引用只证明来源相关，不能单独证明计算正确。

### 认证、隐私与运行

- 使用成熟认证机制，密码不明文保存；会话策略与部署环境匹配。
- 所有读写接口、任务、下载都实施账户级权限校验。
- 密钥只在服务端环境变量中；日志不输出密钥和整份私有资料。
- 模型调用优先传递完成任务所需的最少字段、汇总和定义片段；确需原文/图片时遵循告知的处理方式。
- 文件上传校验类型、大小、路径与资源限制。
- 任务设合理的超时、重试和调用上限；取消后停止新步骤，并说明已发出的远端请求可能已产生用量。
- 不作未经验证的“所有数据完全本地处理”“绝不离开设备”等承诺。
- 演示资料与用户资料隔离；备用示例结果明确标识生成时间。
- 日志记录实际工具输入摘要、结果、耗时和错误；不记录或展示模型隐藏思维链。

### 性能与测试

页面按需加载，大表格分页/虚拟化，昂贵解析放后端任务，图表避免重复渲染。
状态管理区分服务端数据、编辑草稿、当前选择和运行状态。
必须验证浏览器刷新、后端重启、并行任务、不同用户访问、典型错误输入。
优先测试有风险的计算、权限和端到端流程；不要用大量低价值测试掩盖主流程没有跑通。

## 19. 可复现演示案例

### 案例 A：校园满意度调查

明确标记为合成演示数据。

| 范围 | 回收问卷 | 有效且回答该题 | 满意人数 | 按定义计算的满意率 |
| --- | ---: | ---: | ---: | ---: |
| A 学院 | 68 | 60 | 45 | 75% |
| B 学院 | 56 | 50 | 45 | 90% |
| C 学院 | 76 | 70 | 54 | 约 77.14% |
| 合计 | 200 | 180 | 144 | 80% |

定义资料：满意率按“满意人数 ÷ 有效且回答该题的人数”计算。
初始报告：
1. “本次共回收问卷 200 份，其中有效且回答该题的问卷 180 份。”
2. “满意人数为 144 人，全校满意率为 72%。”
3. “满意率比去年提高 8 个百分点。”

图表图片：标题为全校满意率，标注 75%。

预期：
- 第 1 项与输入一致。
- 第 2 项在约定口径下存在差异，144÷180=80%；72% 与使用总回收数作分母的计算相同，但不能据此声称知道作者当时的操作历史。
- 第 3 项证据不足，因为未提供去年对应口径数据。
- 图表 75% 与全校的 80% 不一致；必须正确识别图片内容或要求确认。
- 切换 A 学院后，45÷60=75%；旧结论待复核，报告中“全校”也需要按用途修改。
- 不默认把全校报告整体改成学院报告，用户选择应用范围后才生成相应修订稿。

素材建议：survey.csv、survey.xlsx、metric-definitions.docx、report.docx、chart.png。生成逐行数据时应固定随机种子或确定性生成规则，并由独立断言验证上述汇总。

### 其他案例的已知答案

- 增长案例：50 增加到 60，相对增长 20%；若为占比 50% 升到 60%，增加 10 个百分点。不能混用。
- 加权案例：必须按真实组规模计算总平均，不直接平均各组比例。
- 零基期：0 到正数的相对增长率不能用普通除法给有限百分数。
- 并列排名：两个组同值，按约定规则并列，不凭空创造先后。
- 缺失因果材料：仅有前后数值，不直接证明某项行动造成了变化。

## 20. 评分对应与证据

以下是产品设计映射，不是得分承诺。赛事公开页面的维度权重为：AI 技术深度 35%、创新性 25%、前端工程质量 10%、实用性 10%、用户体验 10%、社会价值与商业潜力 10%。

| 方向 | 本项目的实现 | 评委可检查的证据 |
| --- | --- | --- |
| AI 技术深度 | 模型提取陈述、工作流调度、规则检索、图像识别、工具计算、失败兜底 | 真正的调用结果、引用、工具记录、可复现案例 |
| 创新性 | 句子到证据的定位；规则/范围变更后依赖结果失效；改稿后再核验 | 点击联动和切换范围的现场操作 |
| 前端工程 | TypeScript、可复用组件、状态与路由、表格性能、错误恢复 | 源码结构、测试、构建与运行记录 |
| 实用性 | 从资料到可下载交付件的完整流程 | 用户能完成真实任务；导出文件可继续使用 |
| 用户体验 | 三栏工作台、清楚的状态、简洁操作、窄屏适配 | 可用界面、键盘操作、错误/加载场景 |
| 社会与商业价值 | 减少统计口径误用，帮助理解证据；规则模板支持重复工作 | 实际试用反馈；个人/团队模式作为待验证方案 |

潜在模式：个人使用面向一次性报告；团队使用增加统一规则、复核记录、批量任务和协作权限。收费方式和意愿需验证，首版不做虚构营收、用户规模或付费流程。

### 评测安排

建立至少 30 条可复现用例，建议每类 5 条：正确陈述、数值错误、口径错误、图表不一致、证据不足、范围/语义歧义。再增加权限、超时、导出和版本失效测试。

使用同一批案例对比“直接让模型给判断”与“模型 + 规则检索 + 计算工具”。两者使用相同可获得的材料和明确配置，记录失败案例，不预设胜率。

指标必须注明分母：
- 错误检出率：已发现的真实错误数 / 标注的真实错误数。
- 误报率：被误判为错误的正确陈述数 / 正确陈述总数。
- 证据引用正确率：经人工核对正确的引用数 / 被核对引用总数。
- 不确定情况处理：缺证/歧义用例中是否正确请求补充或确认。
- 运行耗时：记录样本、环境、重复次数与中位数，不能把最顺利一次当普遍结果。

没有真实评测结果时，页面、PPT 和文档均标为待测。

## 21. 6 分 40 秒演示路线

赛事公开材料要求演示视频 5–8 分钟；现场答辩如另有通知，再调整时长。建议目标 6 分 40 秒，留下操作和口误余量。

| 时间 | 展示内容 | 观众看到什么 |
| --- | --- | --- |
| 0:00–0:30 | 首页与问题引入 | 一句看似正确的报告也可能使用错误分母 |
| 0:30–1:05 | 打开调查案例、查看表格与定义 | 数据、报告、图片和规则已经关联 |
| 1:05–1:50 | 自然语言分析各学院满意率 | 真实计算、图表、来源与样本量 |
| 1:50–3:05 | 核验 72% 并展开证据 | 原句、144/180、规则原文三者对应 |
| 3:05–3:45 | 核对图片中的 75% | 多模态与表格结果一起使用 |
| 3:45–4:35 | 筛选 A 学院 | 旧结果待复核；主体与数值一起检查 |
| 4:35–5:20 | 接受修改、补充说明、重新核验 | 修订流程真实变化，缺去年数据仍未解决 |
| 5:20–6:00 | 导出 PDF 与查看个人空间记录 | 交付件可下载，历史版本可追溯 |
| 6:00–6:40 | 测试、实现原理与适用价值 | 已测结果与能力边界、真实技术证据 |

演示前准备独立演示账户和干净案例副本。避免在视频中耗时注册、找文件或等长时间上传。长等待可在剪辑时明确加速，不能把预制结果说成实时 AI 运算。

案例、模板和个人空间不必逐页讲完；主要时间留给真实核验与修改。完整页面是产品能力，演示路线是其中的一条主线。

## 22. 开发顺序和验收门槛

| 阶段 | 交付 | 通过标准 |
| --- | --- | --- |
| 1 | 设计系统、11 页路由和主布局 | 桌面/手机导航可用，核心页关系正确；原型数据明确标注 |
| 2 | 项目、认证、资料上传与持久化 | 两个账户隔离；刷新/重启可恢复；解析错误有反馈 |

| 4 | 大模型、规则检索和核验工作流 | 未写死答案；引用和工具调用真实；不确定情况能暂停 |
| 5 | 图像核验、依赖失效、修改复核与导出 | 完整案例跑通，旧结果不冒充当前结果，文件可打开 |
| 6 | 模板、个人空间、异常恢复与视觉精修 | 所有正式入口有效；没有占位假按钮 |
| 7 | 部署验证、评测、README 和演示材料 | 新环境可复现；测试账户可用；材料一致 |

每完成一个真实模块保存对应 Git 提交，描述实际变化。不要最后一次提交所有功能，也不要倒造开发记录。

### 最终验收清单

- 全部 11 个页面可按权限访问，路径刷新可恢复。
- 自己上传的新样本可计算与核验，不仅内置案例可用。
- 报告一句话能定位数据、规则和计算结果。
- 图像识别有真实调用和不确定分支。
- 更换文件、规则或范围后，相关结果待复核。
- 接受修改后执行新一轮核验。
- 缺少证据时保持未解决，不自动算成通过。
- 三类主要交付文件正常打开、中文正常、版本一致。
- 重新登录能找回项目、收藏和导出记录。
- 用户不能读取其他账户的项目、任务和下载文件。
- 超时、断网、重复点击、解析失败、会话过期不会造成假成功。
- 实际测试结果、代码和演示表述一致。
- README 写明运行方式、环境变量、依赖、支持边界和演示入口。
- 演示视频控制在规定时长，技术文档按比赛要求准备。
